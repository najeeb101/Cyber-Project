# WA-001 - Finding Record

**Status:** Verified (manual), remediated and retested 2026-10-30
**Title:** Missing Content-Security-Policy (CSP) header  
**Affected URL/component:** `http://127.0.0.1:3000/` (all HTML responses, web server configuration)  
**Technical owner:** Member 3  
**Risk reviewer:** Member 4

## Preconditions

None. An unauthenticated client can request the home page.

## Discovery and reproduction

**Discovery method:** OWASP ZAP automated scan (alert "Content Security Policy (CSP) Header Not Set", Medium), then manually verified.

1. Confirm the lab is running on loopback only (`docker port juice-shop`).
2. Run `curl.exe -s -D - -o NUL http://127.0.0.1:3000/`.
3. Inspect the response headers for `Content-Security-Policy`.

## Expected behavior

HTML responses carry a `Content-Security-Policy` header restricting script, style and frame sources, so the browser blocks injected or third-party scripts.

## Observed behavior

The response (HTTP 200) contains `X-Content-Type-Options`, `X-Frame-Options` and `Feature-Policy`, but no `Content-Security-Policy` header. The browser has no policy limiting where scripts may load from.

## Evidence

- `evidence/manual-tests/WA-001-csp-headers.txt`
- `evidence/automated-scans/EV-002-zap-scan-raw.html`

## Analysis

- OWASP category: A02:2025 Security Misconfiguration (OWASP Top 10, 2025)
- Confidentiality impact: Low (indirect). Increases the damage of any XSS, e.g. script-based data theft.
- Integrity impact: Low (indirect). Does not alter data on its own.
- Availability impact: None.
- CVSS-informed severity: Low to Medium. This is a defense-in-depth gap, not directly exploitable alone. Severity rises if XSS is confirmed in the same app (see other findings). Team should compute the final CVSS v3.1/4.0 vector and record it here.
- Confidence and limitations: High that the header is absent (direct observation). Impact depends on whether an injection point exists. Verified on `/` only; other routes were not individually checked.

## Remediation and retest

**Recommended remediation:** Add a restrictive `Content-Security-Policy` header (e.g. `default-src 'self'`, with only the script/style sources the app needs, and `frame-ancestors 'self'`). Test in report-only mode first, then enforce.  
**Remediation method:** Loopback-only nginx reverse proxy that injects the CSP header. Steps, config, and before/after capture: `evidence/05-remediation-retest/WA-001-remediation.md` and `evidence/05-remediation-retest/retest-record.md`.  
**Retest result:** Remediated and retested 2026-10-30. With the proxy running, `http://127.0.0.1:8080/` returns the CSP header; the direct port `:3000` still lacks it (expected - the lab keeps both open for comparison). Same page served (`Content-Length` 9984 unchanged). Evidence: `evidence/05-remediation-retest/WA-001-before.txt`, `WA-001-after.txt`, `retest-record.md`.
