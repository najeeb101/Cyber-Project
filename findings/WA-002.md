# WA-002 - Finding Record

**Status:** Verified (manual), remediation and retest pending  
**Title:** Overly permissive CORS policy (`Access-Control-Allow-Origin: *`)  
**Affected URL/component:** `http://127.0.0.1:3000/` and API routes such as `/rest/products/search` (server-wide CORS configuration)  
**Technical owner:** Member 3  
**Risk reviewer:** Member 1

## Preconditions

None. Any web origin can send a cross-origin request to the application.

## Discovery and reproduction

**Discovery method:** OWASP ZAP automated scan (alert "Cross-Domain Misconfiguration", Medium), then manually verified.

1. Run `curl.exe -s -D - -o NUL -H "Origin: http://evil.example" "http://127.0.0.1:3000/rest/products/search?q=apple"`.
2. Inspect the response headers for `Access-Control-Allow-Origin`.

## Expected behavior

The server allows cross-origin reads only from a short allow-list of trusted origins, and never combines a wildcard with credentialed endpoints.

## Observed behavior

The server returns `Access-Control-Allow-Origin: *` for a request from an arbitrary foreign origin (`http://evil.example`) and on all other responses checked. There is no origin allow-list.

## Evidence

- `evidence/manual-tests/WA-002-cors-headers.txt`
- `evidence/automated-scans/EV-002-zap-scan-raw.html`

## Analysis

- OWASP category: A02:2025 Security Misconfiguration (OWASP Top 10, 2025)
- Confidentiality impact: Low. Browsers will not send cookies with a wildcard origin, so only data readable without credentials is exposed to other sites. Risk grows if any endpoint relies on ambient or token-less access.
- Integrity impact: Low.
- Availability impact: None.
- CVSS-informed severity: Low. Team should compute the final vector and record it here.
- Confidence and limitations: High that the header is present on the tested routes. Practical impact was not demonstrated with a cross-origin browser page. Whether authenticated API calls (using Authorization headers) are readable cross-origin was not tested.

## Remediation and retest

**Recommended remediation:** Replace the wildcard with an explicit allow-list of trusted origins, restrict allowed methods/headers, and do not enable CORS on routes that do not need it.
